# Складской учёт

Учёт материалов, поставщиков и поступлений на склад, отчёт по поставкам.

Стек: Python 3.11+, FastAPI, PostgreSQL 16, SQLAlchemy, Alembic, Jinja2.
Есть графический интерфейс, HTTP API (`/docs`) и авторизация с двумя ролями.
Версии всех зависимостей зафиксированы в `pyproject.toml`.

- Описание API — [docs/API.md](docs/API.md)
- Схема данных и миграции — [docs/DATA_MODEL.md](docs/DATA_MODEL.md)
- Тесты, проверки и покрытие функций — [docs/TESTING.md](docs/TESTING.md)
- Правила внесения изменений — [CONTRIBUTING.md](CONTRIBUTING.md)
- Развертывание на серверах — [deploy/README.md](deploy/README.md)
- Контейнеры, Nginx и несколько экземпляров — [docs/CONTAINERS.md](docs/CONTAINERS.md)
- Непрерывная интеграция (CI), публикация образа, защита приёмки — [docs/CI.md](docs/CI.md)

## Быстрый старт (Linux, WSL2)

Нужны: Python 3.11+ с модулем venv, PostgreSQL 16, GNU make, git, curl
(для `make tools`; `make verify` скачивает gitleaks, trivy, actionlint один раз).

```bash
sudo apt install python3 python3-venv postgresql postgresql-client make git

make setup     # единый сценарий первоначальной настройки (scripts/setup.sh)
make run       # http://127.0.0.1:8000
```

`make setup` выполняет по порядку: проверку программ → виртуальное окружение
`.venv` и зафиксированные версии зависимостей → файл `.env` со случайными
паролями → роль и базы PostgreSQL (рабочая и тестовая, через `sudo -u postgres`)
→ миграции и начальные данные → git-хук `pre-push`. Повторный запуск безопасен:
готовые шаги пропускаются, существующий `.env` не меняется. Пароль администратора
для входа печатается при создании `.env` (`ADMIN_PASSWORD` в `.env`).

Демонстрационные данные (10 поставщиков, 26 материалов, 28 поступлений):
`make demo_seed`.

## Запуск в контейнерах (Docker Compose)

Нужны Docker и Compose v2 (`sudo apt install docker.io docker-compose-v2 docker-buildx`).
Виртуальное окружение и локальный PostgreSQL не нужны.

```bash
make container-env     # пароли в deploy/docker/env/*.env (один раз)
make lock              # requirements.lock, если его ещё нет (нужен доступ к PyPI)
make container-up      # make container-check → сборка → запуск → ожидание готовности
make container-balance # какие экземпляры отвечают через Nginx
```

Приложение доступно только через Nginx: `http://<адрес>/` (порт `HTTP_PORT`, 80).
Изменять окружение — только через `make container-up` (сначала выполняется
`make container-check`). Подробности — [docs/CONTAINERS.md](docs/CONTAINERS.md).

### make verify

Те же шаги выполняет CI (`.github/workflows/ci.yml`) — по заданиям, параллельно;
совпадение локальных и серверных проверок проверяет `make guard`. Подробнее — [docs/CI.md](docs/CI.md).

| Шаг | Команда | Что проверяет |
|---|---|---|
| 1 | `make policy` | Правила проекта: версии зафиксированы и установлены, тесты не пропускаются, пороги не снижены, исключения анализаторов обоснованы (`tools/policy.py`) |
| 2 | `make guard` | Охрана приёмки: pipeline не ослаблен, CODEOWNERS охватывает критические файлы, тесты не удалены, правила не ослаблены относительно основной ветки (`tools/ci_guard.py`); отчёт `reports/guard.md` |
| 3 | `make format-check` | Форматирование кода (`ruff format --check`) |
| 4 | `make lint-check` | Линтер: ошибки, стиль, порядок импортов, `print` в коде (`ruff check`) |
| 5 | `make sast` | Статический анализ безопасности (`bandit`), отчёт `reports/bandit.html` |
| 6 | `make secrets` | Поиск секретов (`gitleaks`): файлы репозитория и коммиты ветки; `reports/gitleaks-*.json` |
| 7 | `make deps-audit` | Известные уязвимости зависимостей образа и окружения (`pip-audit`); `reports/deps-*.md` |
| 8 | `make test` | Unit- и интеграционные тесты на тестовой базе, покрытие не ниже порога; отчёты `reports/junit.xml`, `reports/htmlcov/index.html`, `reports/coverage.xml` |
| 9 | `make mutation` | Мутационная проверка: любое изменение условия в `app/rules.py` должно ловиться тестами; отчёт `reports/mutation.txt` |
| 10 | `make migrations-check` | Миграции на отдельной временной базе; `reports/migrations-check.txt` |
| 11 | `make backup-check` | Резервная копия и восстановление на отдельной временной базе; `reports/backup-check.txt` |

Подробнее — [docs/TESTING.md](docs/TESTING.md).

## Резервное копирование и восстановление

```bash
make backup                          # backups/warehouse-ГГГГММДД-ЧЧММСС.dump
make backups                         # перечень копий
make restore                         # из последней копии (спросит имя базы)
make restore FILE=backups/warehouse-20261008-153000.dump YES=1
```

Копия — архив `pg_dump` в собственном формате; после создания он проверяется
командой `pg_restore --list`, права на файл — 600 (в копии есть хеши паролей).
Восстановление сначала проверяет файл, затем сохраняет текущее состояние базы в
копию `before-restore-…dump` и только после этого заменяет данные — одной
транзакцией: при ошибке база остаётся прежней. Остановите приложение перед
восстановлением. Если копия сделана на более старой версии схемы, после
восстановления выполните `make migrate`.

## Переменные окружения

Все настройки — в `.env` (в репозиторий не попадает, см. `.gitignore`).
Пример со всеми переменными — `.env.example`.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL (обязательна) |
| `SECRET_KEY` | Ключ подписи файла cookie сеанса, ≥ 16 символов (обязательна) |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Учётная запись, создаваемая `make seed` (обязательны) |
| `APP_HOST`, `APP_PORT` | Адрес и порт (по умолчанию 127.0.0.1:8000) |
| `SESSION_HOURS` | Срок действия сеанса, часов (12) |
| `PASSWORD_MIN_LENGTH` | Минимальная длина пароля (8) |
| `INSTANCE_ID` | Идентификатор экземпляра в ответах; по умолчанию имя узла (в контейнере — его ID) |
| `TEST_DATABASE_URL` | Отдельная база для тестов, имя оканчивается на `_test` |

Если обязательной переменной нет, приложение не запускается и пишет, какой
именно переменной не хватает.

## Роли

| Роль | Что доступно |
|---|---|
| Администратор (`admin`) | Всё, включая управление пользователями |
| Кладовщик (`storekeeper`) | Материалы, поставщики, поступления, отчёт |

## Правила предметной области

| Код | Правило |
|---|---|
| БП-01 | Единица измерения задаётся только кодом ОКЕИ — произвольное слово недопустимо |
| БП-02 | Количество больше нуля; для штучных единиц — целое |
| БП-03 | Цена не отрицательна; сумма строки = количество × цена |
| БП-04 | Дата поступления не в будущем и не ранее 01.01.2000 |
| БП-05 | ИНН поставщика: 10 или 12 цифр с верной контрольной суммой, уникален |
| БП-06 | Артикул материала уникален и соответствует формату `CEM-500` |
| БП-07 | Материал не повторяется в одном поступлении |
| БП-08 | Запись справочника, на которую есть ссылки, не удаляется |
| БП-09 | Доступ к операциям — по роли пользователя |
| БП-10 | Пароль не короче 8 символов, хранится только в виде хеша |
| БП-11 | Номер накладной поставщика обязателен; одна накладная поставщика не оприходуется дважды |

Каждое правило проверяется unit-тестами (`tests/unit/test_rules.py`, включая
граничные значения) и интеграционными тестами на настоящей базе
(`tests/integration/`).
