# Развертывание на двух серверах Linux

Стенд: `wa-app01` (192.168.253.130) — приложение, `wa-db01` (192.168.253.131) —
PostgreSQL 16. ОС — Ubuntu Server 24.04 без графического интерфейса. Контейнеры
не используются. Адреса меняются переменными окружения скриптов
(`APP_IP`, `DB_HOST`, `SSH_SUBNET`, `APP_PORT`).

## Порядок

Все скрипты запускаются из корня распакованного проекта через `sudo`.
Повторный запуск любого из них безопасен.

| Шаг | Машина | Команда | Пункты задания |
|---|---|---|---|
| 1 | обе | `sudo bash deploy/common/setup_admin_ssh.sh waadmin /tmp/win.pub /tmp/wsl.pub` — один или несколько ключей (файлы `.pub` или строки) | 2, 3 |
| 2 | wa-db01 | `sudo bash deploy/db/setup_db.sh` — выводит пароли ролей один раз | 5, 6, 10 |
| 3 | wa-app01 | `sudo bash deploy/app/setup_app.sh` — спрашивает пароли ролей | 3, 4, 5, 8, 10, 11 |
| 4 | wa-app01 | `sudo bash deploy/app/deploy_app.sh` (`DEMO=1` — с демо-данными) | 7, 8, 9 |
| 5 | обе | `sudo bash deploy/check.sh` — проверка требований | 13 |

Обновление приложения — только шаг 4 с новой копией проекта.

## Файлы

| Файл | Назначение |
|---|---|
| `app/warehouse.service` | unit-файл systemd: пользователь `warehouse`, `Restart=on-failure` |
| `app/warehouse.env.example` | образец `/etc/warehouse/warehouse.env` (настройки службы) |
| `app/migrate.env.example` | образец `/etc/warehouse/migrate.env` (пароль владельца БД для миграций) |

## Требования, которые соблюдаются

- Вход под root по SSH недоступен: для root (`Match User root`, `MaxAuthTries 0`)
  sshd разрывает соединение на первом запросе входа, не проверяя ни ключ, ни пароль.
- Приложение не запускается от root: `User=warehouse`, системная учётная запись без оболочки.
- Лишние порты не открываются: ufw `deny incoming`; открыты 22 (из подсети),
  8000 (wa-app01) и 5432 только для 192.168.253.130 (wa-db01).
- Пароли не хранятся в репозитории: настоящие значения лежат только в
  `/etc/warehouse/*.env` (root, 600); в репозитории — образцы `*.example`,
  `.env` исключён в `.gitignore`.
- Роль БД приложения `wh_app` имеет только SELECT/INSERT/UPDATE/DELETE;
  схему меняет `wh_owner`, и только при развертывании.
